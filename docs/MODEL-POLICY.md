# 模型能力分级与升级策略

DeepStack 不根据模型品牌、版本号或宣传名称判断能力。能力必须由当前任务中的可观察结果证明。模型分级描述本轮需要的保证强度，不是对某个模型的永久评级。

## 三个等级

| 等级 | 适用任务 | 最小流程 | 不能省略的证据 |
|---|---|---|---|
| `L0` 常规 | 范围小、目标清楚、可逆、没有外部写入 | 单模型执行 + 项目已有质量门 | 受影响检查通过或明确未配置 |
| `L1` 工程 | 多文件、需求有歧义、需要设计或回归保护 | 目标/方案 → 实现 → 质量门 → 自检 | 方案、改动范围、测试和未验证项 |
| `L2` 关键 | 安全、数据迁移、权限、生产、外部写入、大 diff 或高代价错误 | 架构判断 → 实现 → 独立上下文/模型审查 → 人工或授权门 | 独立审查证据、回滚方案和明确授权 |

## 自动升级触发器

只要命中一项，就至少升到 `L1`；命中关键风险时升到 `L2`：

- 跨模块、跨仓库或改变数据/权限边界
- 数据迁移、删除、认证、安全或生产配置
- 外部写入、提交、推送、合并、发布或部署
- 需求无法形成可观察验收标准
- 质量门失败、同一问题反复返工或模型无法解释失败
- diff 大、影响面不明或缺少回归测试

任务风险降低时可以回到较低等级，但必须说明原因。升级是增加证据和审查，不是盲目增加代理数量。

## 只有一种模型时

单模型是合法运行方式，不需要为了形式再造多个代理：

1. `L0` 直接执行并运行确定性质量门。
2. `L1` 让同一模型分离“方案、实现、自检”三个阶段；每阶段重新检查目标、范围和证据。
3. `L2` 优先暂停外部写入，要求人工确认或切换到独立模型/独立上下文。
4. 如果只能继续使用同一模型，执行顺序化多视角审查，但结果必须标记 `SAME_MODEL_REVIEW`，不能称为独立审查。
5. 任何质量门失败、证据缺失或连续两次返工，都应停止扩大范围，输出阻塞和升级建议。

## 输出契约

每次进入内部步骤时报告：

```text
路由器状态：<已路由 / UNVERIFIED>
路由：<主流程>
模型策略：L0 / L1 / L2
降级：<无 / SAME_MODEL_REVIEW / ROUTER_UNVERIFIED>
可用模型：<当前注册表中的名称 / 未确认>
```

字段名必须逐字使用上面的五个名称；不得用 `主流程`、`升级触发` 或 `本轮降级` 代替它们。

模型名称只能作为记录，不能作为能力证据。真实测试、质量门和独立审查结果优先于模型自述。

仓库内的 `scripts/model-policy.mjs` 只根据任务文字给出 `L0/L1/L2` 和触发器。它看不到宿主有几个模型，默认 `independentReview` 为 `unknown`；这时 `L2` 的 `fallback` 是 `未确认`，不能写成 `SAME_MODEL_REVIEW`，也不能写成已经有独立审查。调用方证明没有独立审查时，才传 `--independent-review absent` 或 `--single-model`，`L2` 才标 `SAME_MODEL_REVIEW`。证明已有独立审查时传 `--independent-review present`，`fallback` 为 `无`，`可用模型` 仍是 `未确认`。原有调用方式不变：位置参数和标准输入仍是任务原文。模型判断不得低于脚本给出的等级。否定只覆盖同一分句里、重新提出要求之前的那个动作；后一句里的生产、认证、部署或数据破坏仍然算数。

如果宿主没有确认 `single-entry`、`skill-loading` 和 `model-policy`，自动升级状态必须标记为 `ROUTER_UNVERIFIED`。没有读取当前宿主模型注册表或得到真实模型探测结果时，`可用模型` 必须写 `未确认`。此时只能报告模型自身的建议，不能把它称为 DeepStack 的 `L0/L1/L2` 决策，也不能把模型列出的名称当成可用模型清单。
